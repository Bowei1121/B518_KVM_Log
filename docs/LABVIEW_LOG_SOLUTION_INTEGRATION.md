# LabVIEW、JetKVM Log 與 Log Solution 配合規格

日期：2026-10-14（Asia/Taipei）
狀態：需求已確認。使用者於 2026-10-14 回覆 A18「同意」，確認 Q1–Q17 的整體整理符合共同理解；尚未實作與現場驗收。
範圍：跨程式責任、輪次流程與結果交付。不是已完成實作、發布或現場驗收紀錄。

## 三個程式的責任

| 程式 | 責任 |
| --- | --- |
| LabVIEW | 掌握本輪投入位置及 SN，產生輪次 UUID，控制輸入、啟動測試、等待結果及後續設備動作 |
| JetKVM Log 橋接程式 | 依 LabVIEW 指令透過 JetKVM 操作 ATE、擷取畫面及回報結果，保存已確認結果並處理重傳與接收確認 |
| B518 Log Solution | 在 ATE 電腦讀取 Log，管理測試輪次與人工確認，以人機畫面的標記與色帶提供正式結果 |

DFU、FCT、BT 全部以 Log Solution 作正式結果來源。原本 ATE 軟體畫面仍可用於操作定位；結果判讀以 Log Solution 為準。

## 位置與產品

- 第一排由左至右為 Slot 1–10，第二排為 Slot 11–20；Slot 1、Slot 11 分別是各排第一格。
- LabVIEW 與畫面共用 Slot 編號；不同測試平台來源通道的差異由 Log Solution 配置映射。
- LabVIEW 知道本輪實際投入位置及各位置 SN。配置容量不等於投入數量，空位置不是本輪產品。
- 結果色帶只提供位置及狀態，沒有 SN。LabVIEW 依本輪清單對應 SN；不能宣稱已從色帶核對 SN。
- 固定、跨工站唯一設備 ID 暫採為方向，實際命名與設備／KVM IP 配置尚未完成。若 LabVIEW 已有唯一編號，優先沿用。

## 輪次開始與等待

目標順序：

1. LabVIEW 建立本輪 UUID 與投入清單。
2. 依 LabVIEW 指令輸入 SN。
3. 啟動 Log Solution 監控。
4. 橋接程式確認畫面已進入監控中。
5. 啟動 ATE 測試。
6. 等待 Log Solution 本輪結果可取用。

橋接程式不自主啟動下一輪；ATE 與治具後續動作由 LabVIEW 控制。

## 結果與待確認

- WAITING／TESTING 是等待狀態，不能當產品 FAIL。
- 結果衝突或未確認警報顯示待確認時，橋接程式立即通知 LabVIEW 暫停後續設備動作。
- 人員在 Log Solution 完成確認後，才繼續取用本輪結果。
- 本輪結果已可靠確認可取用後，投入產品的 PASS 按良品處理；FAIL／NOTEST／TIMEOUT 均按不良品處理，再由人工判定後續。
- Log Solution 保留原始狀態作追查；上述 PASS／FAIL 是 LabVIEW 的產品處置分類。
- 斷線、畫面不可辨識、版本不符或不能確認同輪屬於通訊／畫面異常，暫停流程，不能直接轉成產品 FAIL。
- 橋接程式須以可靠完成與逐格結果判斷取用，不能只看現有總欄位 `result=PASS`。

## UUID 的範圍

- 每輪 UUID 由 LabVIEW 產生；同輪查詢及重傳沿用，下一批或重新測試換新，即使 SN 相同亦不重用。
- UUID 只在 LabVIEW 與 JetKVM Log 橋接程式之間使用，確認同輪指令、結果與 ACK。
- 不將 UUID 傳入 ATE／Log Solution，不增加 JetKVM 鍵盤輸入 UUID，也不新增 UUID 畫面標記。
- Log Solution 自己的內部 round_id 保持獨立。橋接側 UUID 不是 ATE 原始 Log 或畫面同輪性的證據。
- `req_id` 識別單次通訊；輪次 UUID 識別一輪。協定欄位與指令的具體設計屬於後續實作工作。

## 完整交付與重傳

1. 橋接程式取得並可靠確認完整本輪結果。
2. 完整結果必須保存至重啟後仍可恢復，然後才向 LabVIEW 交付；此順序是落實已確認重啟恢復需求的必要條件。
3. LabVIEW 只在完整 JSON 訊息到齊、設備／UUID／位置清單核對成功後採用結果；不完整訊息不得觸發設備動作。
4. LabVIEW 回覆結果接收確認（ACK）。橋接程式未收到 ACK 前保留結果供同輪重傳。
5. 重傳同一輪既有結果不代表重新測試。LabVIEW 按設備及 UUID 防止重複執行設備動作。
6. 結果已收到與設備動作已完成是不同狀態。橋接程式不把傳送成功視為接收成功，也不把 ACK 視為設備動作完成。

## 斷線與重啟

| 情況 | 目標行為 |
| --- | --- |
| 只有 LabVIEW TCP 斷線，橋接程式仍運行 | 保留原輪次並繼續；重連使用同一 UUID |
| 橋接程式重啟，已有可靠保存的完整結果 | 恢復並按設備與 UUID 重傳；不自動重做設備動作 |
| 橋接程式重啟，本輪尚無可靠保存結果，無法確認畫面同輪性 | 暫停，人工核對；不自動取用殘留完成畫面或重新測試 |

## 新輪次與保存期限

- 同一設備上一輪未 ACK 時拒絕開始新 UUID；須先完成交付，或明確取消並留紀錄。
- 不以新輪次覆蓋未交付結果。
- 已 ACK 結果自接收確認起保留 14 天，供查核與同輪重傳。
- 未 ACK 結果不因上述期限自動清除。
- 14 天是橋接結果交付記錄的期限，不修改 Log Solution 既有輪次紀錄保存設定。
